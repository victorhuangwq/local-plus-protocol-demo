local+ protocol demo

Two links. No app to install. See where Chromium stops a webpage from opening a local-only app protocol.

Browser setup required. Use a desktop Chromium-based build containing change 8382199 and explicitly enable LocalOnlyAppProtocolPrefix. The change landed disabled by default. This page cannot enable or detect the feature. See the Windows and macOS launch instructions.

Try it

  1. Open DevTools with F12 or Ctrl+Shift+J on Windows, or Command+Option+J on macOS. Select Console and make sure errors are visible.
  2. Click each link below separately. Compare the browser's console messages. The page may look unchanged; the console is the evidence.

Ordinary protocol

toydemo:hello

Try ordinary protocol

Expected: normal external-handler lookup. On Windows and macOS with no app registered, the console reports that the scheme has no registered handler.

Local-only protocol

local+toydemo:hello

Try local-only protocol

Expected with the feature enabled: the browser blocks the request before handler lookup:

Not allowed to launch 'local+toydemo:hello'.

What this demonstrates

The browser checks the requested scheme for the literal local+ prefix. toydemo: and local+toydemo: are independent names, not aliases. Even a deliberate click on a webpage is web-initiated.

These are expected outcomes, not live status indicators. A webpage cannot reliably tell whether an external app launched or read these browser-generated console messages.

No app is supplied or installed. If you already have an app registered for either demo scheme, the ordinary launch flow may offer to open it; cancel that prompt if you do not want to open the app.

If both links behave the same

Check that your browser actually contains the change and that you launched a separate test instance with --enable-features=LocalOnlyAppProtocolPrefix. An older browser can accept an unknown feature flag without implementing it. A fresh profile does not remove device-level enterprise policies.

As a control, use the same compatible browser in another fresh profile with --disable-features=LocalOnlyAppProtocolPrefix. Both links should then follow normal handler lookup, assuming no overriding policies or other restrictions.

Limits

This demonstrates rejection, not successful app launching. Typing a local-only URL directly into the address bar retains the normal launch flow, but opening an app still requires a registered handler.

This is browser enforcement, not OS access control. Administrator policies AutoLaunchProtocolsFromOrigins and applicable URLAllowlist settings can override the block; remembered user allowances cannot. Other browsers or builds may behave differently.
