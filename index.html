Local-only URLs for desktop apps

Sometimes you want other apps to open your app through a URL, but not websites. That's what the local+ prefix is for.

If your Windows or macOS app handles URLs like myapp:hello, you can register local+myapp instead. Browsers that support this feature block website launches of those URLs when the feature is enabled. Other native apps can still open them through the OS.

On Windows, register local+myapp the same way you register any custom protocol. On macOS, add it to your app's URL schemes. Leave off the colon when registering the name.

Update the apps that call yours to use local+myapp:hello, and check that your URL handler accepts the new name. The browser won't translate myapp: into local+myapp: for you.

If you keep myapp: registered for the same actions, websites can still use that URL. Adding a second name doesn't protect the old one.

Your app still needs to validate incoming URLs. This check happens in the browser, not Windows or macOS. Browsers without the feature may allow the launch, and admins can make exceptions.

Try it

You don't need to install an app for this demo. Click the two links and compare the console messages: one should report a missing app, the other a blocked launch.

Set up your test browser

Use the latest Chrome Canary or Edge Canary. Quit it completely, including any background processes, then run the command for your browser below. If it's still running, the flag may not take effect.

Open this page in the new window. You'll be using your usual Canary profile, settings, and sign-ins.

Windows (PowerShell)

Chrome Canary:

& "$env:LOCALAPPDATA\Google\Chrome SxS\Application\chrome.exe" --enable-features=LocalOnlyAppProtocolPrefix

Edge Canary:

& "$env:LOCALAPPDATA\Microsoft\Edge SxS\Application\msedge.exe" --enable-features=LocalOnlyAppProtocolPrefix

macOS (Terminal)

Chrome Canary:

open -a "Google Chrome Canary" --args --enable-features=LocalOnlyAppProtocolPrefix

Edge Canary:

open -a "Microsoft Edge Canary" --args --enable-features=LocalOnlyAppProtocolPrefix

The commands assume Canary is installed in its usual location. They don't install anything. The page itself can't turn the feature on or check whether it's enabled.

  1. Follow the browser setup above to enable the feature.
  2. Open DevTools with F12 or Ctrl+Shift+J on Windows, or Command+Option+J on macOS. Choose Console and show both Info and Error messages.
  3. Click each link below, one at a time. Look at the console for the result, not the page.

Ordinary protocol

toydemo:hello

Try ordinary protocol

The browser looks for an app that handles this URL. If you haven't registered one, the console says the scheme has no registered handler.

Local-only protocol

local+toydemo:hello

Try local-only protocol

With the feature enabled, the browser blocks this link before looking for an app. You should see:

Not allowed to launch 'local+toydemo:hello'.

The "Searching for..." line comes from this page and just confirms your click. The browser's message after it tells you what happened. The page can't read that message or reliably tell whether an app opened.

If you've already registered an app for either demo URL, you may get a prompt to open it. Cancel if you don't want to launch it.

If both links behave the same

Check that Canary is up to date and that you quit it completely before running the setup command. Older builds can silently ignore a feature flag they don't recognize. On a work device, check whether your organization's browser policies allow the launch.

To compare with the feature off, quit Canary and run the same command with --disable-features=LocalOnlyAppProtocolPrefix instead. Both links should then look for an app, unless another browser rule or policy prevents it.

Testing with your own app

Register a local+ scheme with your app, then try opening its URL from a webpage and by entering it directly in the browser's address bar. With the feature enabled and no admin exception, the webpage link is blocked, even when you click it yourself. The address-bar entry can still open your app through the usual prompt. A native app can also open the URL through the OS.

Admins can allow website launches through AutoLaunchProtocolsFromOrigins or, where supported, URLAllowlist. A user's saved permission to open the app doesn't override the block.
